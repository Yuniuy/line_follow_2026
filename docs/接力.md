## 代码结构（新写的这层，别搞混）

```
src/                  ← 手写业务代码，CubeMX 永远不动这里
├── bsp_config.h      唯一引脚映射表 + 全部可调参数
├── bsp_led.c/.h      LED 两路：On/Off/Toggle/Set/AllOff
└── bsp_key.c/.h      按键四路：KEY_Scan() 非阻塞扫描，事件位图
```

Keil 里对应组叫 `Application/User/BSP`，包含路径里有 `../src`。
这两样都是脚本第 4 项自动维护的，CubeMX 重新生成后跑一次脚本就回来。

### 按键 API 怎么用

```c
KEY_Init();                                   // main 里初始化一次
while (1) {
    KEY_Scan();                               // 每圈都调，别加 delay
    if (KEY_TakeEvent(KEY_ID_1, KEY_EVENT_CLICK)) { /* 短按 */ }
    if (KEY_TakeEvent(KEY_ID_2, KEY_EVENT_LONG))  { /* 长按 800ms */ }
}
```
- 事件是位图，`DOWN / UP / CLICK / LONG` 可同时攒着不会丢
- `KEY_TakeEvent()` **读后即焚**，所以不会一次按键触发两回

## 已知的坑（会重复踩）

- CubeMX 点 Generate Code 后如果卡很久，是在后台下载/解压固件包（100MB 量级），**不是死机，别关**
- 引脚忘了填 User Label，`main.h` 的 `Private defines` 是空的 → 所以才有 `src/bsp_config.h` 集中定义，别在 .c 里直接写 `GPIO_PIN_12`
- **按键是 `GPIO_NOPULL`**：CubeMX 里配的无上下拉，按键接 GND 会悬空乱跳。`KEY_Init()` 里已补内部上拉，别以为硬件坏了
- **自己写的 `src/*.c` 会被 CubeMX 踢出工程** → 重新生成后必须先跑 `fix_keil_after_cubemx.py`
- 开了两个 CubeMX 实例会报 `Updater is already in use`，`taskkill /F /IM javaw.exe` 全杀后重开
- CubeMX 启动时如果 MCU 列表 0 项，那是器件库还没加载完，**重启 CubeMX**
- LED 极性不确定：`LED_ACTIVE_HIGH` 设 1，如果发现「常亮/常灭」反了，改成 0 就行，不会烧
